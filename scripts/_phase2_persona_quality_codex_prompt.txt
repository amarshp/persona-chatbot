BUILD scripts/eval_persona_quality.py — council step 4

PURPOSE
Validate the V01-V10 -> persona-quality correlation. Council's deepest
concern: we may be optimizing a vanity metric. Take retrieval-heavy
smoke tests and generate Fang Yuan responses under two retrieval
configs. Side-by-side markdown for manual review.

DESIGN
The smoke tests in scripts/smoke_test_runner.py have hand-labeled
PASS/FAIL criteria for each question. Reuse them directly. Pick a
subset that should be retrieval-sensitive (in_wiki_grounding +
near_wiki_synthesis = ST-01..ST-06 = 6 questions). Skip out_of_wiki
traps and earth_advice for this experiment — they're not the right
probe for retrieval quality.

For each of the 6 questions, generate two responses:
  CONFIG A: MQ + CRAG retrieval (current Phase 2 best)
            - Use multi_query_retrieve(question, n=3, client=judge_client,
              cached_phrasings=None) — note: smoke test queries are NOT
              in the V01-V10 cache, so multi_query_retrieve will rephrase
              live with temp=0. That's fine — we're measuring retrieval
              effect, not measuring V01-V10 here.
            - Apply crag_filter(question, list(mqr.merged_sections),
              threshold=7, k_max=12, client=judge_client)
            - format_sections(list(crag.survivors)) -> l3_context
  CONFIG B: No retrieval at all
            - l3_context = ""

For each config, build the messages with PromptComposer.build(
[], state, l3_context=l3_context) (matches smoke_test_runner.py:278).

Generate response with PRIMARY_MODEL, temperature=0.7,
max_tokens=MAX_OUTPUT_TOKENS, purpose="persona_quality_eval".

scripts/eval_persona_quality.py — NEW. Self-contained. Run from project
root:

Default: ST-01..ST-06.
