PURPOSE
Diagnostic file that probes specific gaps in the current Phase-1 retriever.
Each test category corresponds to one of the planned future phases — running
the file tells us whether that phase is actually justified by a measured gap,
or whether the current system already handles it. NO LLM CALLS. Pure
inspection of `v1.retrieval.wiki_retriever.retrieve(query)` output.

THE RETRIEVER OUTPUT FORMAT
`retrieve(query)` returns a string of section blocks separated by
`\n\n---\n\n`. Each block starts with a header line of the form:
    ## {section_title} — {page_rel}
…where {page_rel} is e.g. `decisions/extortion_campaign.md` and
{section_title} is e.g. `Key Events`. To detect a specific (page, section)
in the output, check that the EXACT line `## {section_title} — {page_rel}`
appears in the result string.

# scope). Fail means retrieve() confidently returns multiple sections that
# don't actually answer the query — those would be false positives, the

DECISION RULES (encode these in the summary line)
- Phase 2/4 trigger ACTIVE if vocab fails ÷ vocab total ≥ 0.30; else INACTIVE.
- Phase 3 trigger ACTIVE if average sections_returned across COVERAGE_TESTS ≥ 3
  AND average total_tokens ≥ 1800 (i.e. retrieval is confidently surfacing
  content for topics with no dedicated page). Else INACTIVE.
- Out-of-scope regression: PASS if average sections_returned across
  OUT_OF_SCOPE_TESTS ≤ 1; "soft-leak" if 1 < avg ≤ 2; "clear-leak" if > 2.
