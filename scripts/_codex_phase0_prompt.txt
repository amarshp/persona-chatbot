## Context

The project is a Fang Yuan persona simulation system. The wiki retriever (v1/retrieval/wiki_retriever.py) does keyword matching on page tags+summary from shared/data/wiki/index.md, scoring pages by how many query words appear in their tags or summary. Score threshold is >= 2. Budget is L3_BUDGET = 2500 tokens (approximated as chars / 4 = 10,000 chars max).

There are 24 content pages in shared/data/wiki/ organized in subdirectories: philosophy/ (4 pages), decisions/ (9 pages), relationships/ (6 pages), events/ (4 pages), plus index.md and some meta files.

## Script 1: scripts/wiki_token_profile.py

Profile all wiki content pages for token estimates.

Requirements:
- Skip non-content files: index.md, SCHEMA.md, CONVENTIONS.md, TEST_PROMPTS.md, TEST_RESULTS.md
- For each content page:
  - Read the file
  - Count characters
  - Estimate tokens as chars // 4 (same formula the retriever uses: _CHARS_PER_TOKEN = 4)
  - Flag if token estimate > 2500 (exceeds L3_BUDGET alone)
- Print a sorted table (largest first) showing: relative path, chars, tokens, over_budget flag
- Save results as JSON to results/v1/wiki_token_profile_<YYYYMMDD_HHMMSS>.json with structure:
  {
    "generated": "<timestamp>",
    "l3_budget_tokens": 2500,
    "l3_budget_chars": 10000,
    "pages": [
      {"path": "decisions/rebirth_and_spring_autumn_cicada.md", "chars": 4521, "tokens": 1130, "over_budget": false},
      ...
    ],
    "pages_over_budget": ["path1", "path2"],
    "total_wiki_tokens": 12345
  }
- The script must run from the persona-chatbot/ directory: py scripts/wiki_token_profile.py

## Script 2: scripts/retrieval_diagnostic.py

Run all 14 smoke test queries through the retriever's internal logic and log diagnostics.

Requirements:
- Hard-code the 14 queries exactly as listed below (do NOT call the LLM -- this is analysis only)
- For each query:
  1. Extract keywords using the same logic as wiki_retriever._query_words()
  2. Load and parse the index using wiki_retriever._parse_index()
  3. Score every page using wiki_retriever._score()
  4. Identify: pages with score >= 1 (candidates), pages with score >= 2 (selected)
  5. Simulate budget allocation: walk through selected pages in score order, track chars used, flag if any page was truncated
  6. Record: query_id, query_text, keywords (sorted list), all_scored (list of {path, score} for score >= 1), selected (list of {path, score, chars, tokens}), total_chars_used, total_tokens_used, truncated (bool), retrieval_result ("wiki" if any selected else "none")
- Print a summary table per query showing: ST-id, #keywords, #candidates, #selected, tokens_used, truncated
- Save full results as JSON to results/v1/retrieval_diagnostic_<YYYYMMDD_HHMMSS>.json with structure:
  {
    "generated": "<timestamp>",
    "queries": [<per-query record as described above>, ...]
  }
- The script must run from the persona-chatbot/ directory: py scripts/retrieval_diagnostic.py
