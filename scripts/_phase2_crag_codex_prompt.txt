1. v1/retrieval/crag_filter.py — NEW
   Self-contained module. Public API:

       from dataclasses import dataclass
       from v1.retrieval.wiki_chunker import WikiSection
       from shared.llm_client import LLMClient

       @dataclass(frozen=True)
       class CragJudgement:
           lexical_score: int           # original keyword score from retrieve_sections
           crag_score: int | None       # 1..10, or None on call/parse failure
           kept: bool                   # True if survived the threshold
           error: str | None            # populated on failure
           section: WikiSection

       @dataclass(frozen=True)
       class CragResult:
           judgements: tuple[CragJudgement, ...]   # one per input candidate, in input order
           survivors: tuple[tuple[int, WikiSection], ...]  # for downstream format_sections

       def crag_filter(
           query: str,
           candidates: list[tuple[int, WikiSection]],
           *,
           threshold: int = 7,
           k_max: int = 12,
           client: LLMClient | None = None,
       ) -> CragResult:
           """Score each of the top k_max candidates 1-10 for relevance to
           `query`. Drop scores < threshold. Sections that fail to score
           (call/parse error) are KEPT with crag_score=None, error set."""

   Implementation notes:
   - Take candidates[:k_max] (already sorted by descending lexical score
     from retrieve_sections).
   - For each candidate: one JUDGE_MODEL call.
       Prompt template (literal — no .format() with braces):
           SYSTEM: you are a relevance scorer. Reply with one integer 1-10 only. No words, no JSON, no punctuation.
           USER: Query: <query>
                 Section title: <section_title>
                 Section content (truncated to ~600 chars):
                 <content[:600]>
                 Score 1-10 for how well this section answers the query. Reply with the integer only.
     temperature=0, max_tokens=8.
   - Parsing: strip whitespace, take first integer 1-10 found via regex
     `r"\b(10|[1-9])\b"`. If none, treat as error.
   - Survivors: kept sections sorted by (-lexical_score, page_rel, section_title)
     (preserve the existing sort order so format_sections's behavior is
     stable).
   - On client init failure: return all candidates as kept with error set.
